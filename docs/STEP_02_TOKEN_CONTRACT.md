# Step 02 — semantic-token contract and compatibility policy

**Status: owner-approved baseline, not an implementation.** The owner approved the Step 02 gist: retain existing `--lb-*` names and eight families, align runtime surface mappings with the static 1/2/3/4/5 sequence in both modes, preserve the current border/shadow baseline, validate on-fill/alpha/inverse behavior, and avoid removals/renames in the first pass. Step 01 is the [public-surface audit](audits/01-public-surface.md); the acceptance gate is in [execution plan §02](EXECUTION_PLAN.md#L27-L31). Nothing in product code, package exports, generated metadata or `CHANGELOG.md` has changed. The choices explicitly deferred below are **not** approved as new APIs or theme behavior.

## Baseline and comparison

LittleBrand's existing `--lb-*` semantic names are already used by consumers and components: Button uses `--lb-fill-{color}-normal/hover/active`, `--lb-text-on-{color}` and `--lb-surface-{color}-normal/hover/active` ([Button](../src/components/Buttons/Button/LbButton.vue#L280-L326)); Input uses neutral/error borders ([Input](../src/components/Inputs/Input/LbInput.vue#L250-L299)); README shows custom property overrides ([README](../README.md#L184-L205)); the demo uses neutral, primary, global surface and fill variables ([demo](../examples/App.vue#L3946-L3995)). `applyTheme()` currently writes inline semantic values with different surface steps ([generator](../src/utils/color-generator.js#L56-L106), [application](../src/utils/color-generator.js#L191-L210)). These are reasons to keep the *names* and reconcile values, not evidence that custom overrides work in all themes. See [Step 01 token matrix](audits/01-public-surface.md#L79-L91).

Product Design Sandbox's local `develop` checkout at `d71cbbf` has a useful *role* reference: text `on-fill`, surface 1–5 and alpha 3–5, fill 9/10/8, border line/normal/active/focus/disabled, and shadows ([reference theme](https://github.com/drivevelocity/product-design-sandbox/blob/d71cbbf/src/styles/_theme.sass#L15-L56), [surface](https://github.com/drivevelocity/product-design-sandbox/blob/d71cbbf/src/styles/_theme.sass#L64-L124), [fill/border/shadows](https://github.com/drivevelocity/product-design-sandbox/blob/d71cbbf/src/styles/_theme.sass#L129-L219)). Its unprefixed `--text-primary-high-contrast` and `light-dark()`/`color-scheme: light dark` are **not** LittleBrand's contract ([reference](https://github.com/drivevelocity/product-design-sandbox/blob/d71cbbf/src/styles/_theme.sass#L8-L25)); it has fewer color families, different border active/focus steps and an extra `shadow-xl`. The linked public page was unavailable to anonymous fetch (404); this comparison uses the local sibling checkout at the stated commit, which needs owner confirmation if that is not the intended reference revision. Do not copy the syntax, names or mode policy. Theme-selector mechanics belong to Step 03.

## Approved baseline grammar and roles (existing names; subject to validation)

Let `{c}` be one of **primary, secondary, tertiary, neutral, success, warning, error, info**. All eight remain supported; `tertiary` is a distinct sky scale, `info` a blue scale ([palette](../src/styles/_colors.sass#L63-L105)); runtime defaults enumerate the eight ([generator](../src/utils/color-generator.js#L136-L146)). Raw scale `{c}-1…12` and `{c}-alpha-1…12` are *primitives*, not semantic state names. In the tables, `L[n]` means light palette step `n`, `D[n]` dark palette step `n`; `A[n]` is the corresponding theme's alpha step. Mapping is the same **number** in light and dark, but different palette *values*; do not substitute light steps for dark steps. The static dark selectors already remap the scale ([palette](../src/styles/_colors.sass#L693-L707), [theme](../src/styles/_theme.sass#L640-L656)). Step 03 decides exactly how the active mode is selected and how `applyTheme()` keeps inline values in sync.

| Existing semantic name | Role / use | Light → dark target |
|---|---|---|
| `--lb-text-{c}-normal`, `-contrast-high`, `-contrast-low`, `-disabled` | Reading text, emphasized text, lower-emphasis text, disabled text; high/low express emphasis, **not** a promise of accessibility contrast | L[11]/[12]/[9]/[7] → D[11]/[12]/[9]/[7] ([static](../src/styles/_theme.sass#L118-L165), [runtime](../src/utils/color-generator.js#L70-L75)) |
| `--lb-text-on-{c}`, `--lb-text-on-{c}-hover`, `--lb-text-on-{c}-active` | Text/icons on each fill state, not text on tinted surfaces | Existing stable light or dark neutral text, chosen **per family × mode × state** by measured contrast against actual fill. Current static choice: dark for warning, light for the other seven ([theme](../src/styles/_theme.sass#L268-L309), [dark](../src/styles/_theme.sass#L742-L782)); treat as candidates, not certified results. Custom theme generator's current step-9 lightness heuristic ([generator](../src/utils/color-generator.js#L77-L97)) is insufficient to promise all state contrasts. |
| `--lb-surface-{c}-base`, `-subtle`, `-normal`, `-hover`, `-active` | Base canvas, one-step subtle layer, tinted surface, pointer hover, **selected/pressed** state, respectively; state is not keyboard focus or elevation | L[1]/[2]/[3]/[4]/[5] → D[1]/[2]/[3]/[4]/[5] ([static](../src/styles/_theme.sass#L173-L183), [dark](../src/styles/_theme.sass#L646-L656)); runtime must stop using 1/2/3/4 for subtle/normal/hover/active ([generator](../src/utils/color-generator.js#L99-L105)). |
| `--lb-surface-{c}-normal-alpha`, `-hover-alpha`, `-active-alpha` | Same surface roles over *the actual underlying surface*, not opaque color substitutes | L A[3]/A[4]/A[5] → D A[3]/A[4]/A[5] ([static](../src/styles/_theme.sass#L179-L181), [dark](../src/styles/_theme.sass#L652-L654)); runtime generates alpha primitives but must preserve semantic references for custom palettes ([generator](../src/utils/color-generator.js#L238-L259)). |
| `--lb-surface-{c}-base-inverse`, `-subtle-inverse` | Opposite-mode base/subtle preview surfaces, **not** shadow/elevation | On light use D[1]/D[2]; on dark use L[1]/L[2] ([static](../src/styles/_theme.sass#L182-L183), [dark](../src/styles/_theme.sass#L655-L656)). Static references to `--lb-{c}-dark/light-1/2` have no definitions in the palette mixin; runtime creates these only after `applyTheme()` ([palette](../src/styles/_colors.sass#L466-L582), [generator](../src/utils/color-generator.js#L216-L235)). Step 06 must make existing inverse names resolvable **without** a JS call and correct after custom themes; browser verification remains necessary. |
| `--lb-fill-{c}-normal`, `-hover`, `-active`, `-disabled` | Solid interactive fill; pressed fill may be lighter than hover; disabled is translucent, not a general canvas | L[9]/[10]/[8]/A[4] → D[9]/[10]/[8]/A[4]; neutral disabled uses A[2] in both modes ([static](../src/styles/_theme.sass#L69-L116), [runtime](../src/utils/color-generator.js#L63-L68)). |
| `--lb-border-{c}-line`, `-normal`, `-active`, `-focus`, `-disabled` | Hairline/divider, control outline, active selection, keyboard focus **color**, disabled outline | L[5]/[7]/[9]/[7]/A[4] → D[5]/[7]/[9]/[7]/A[4]; neutral disabled A[2] ([static](../src/styles/_theme.sass#L12-L67), [runtime](../src/utils/color-generator.js#L56-L61)). Do not silently adopt Sandbox's active [8] or focus alpha [7]. |
| `--lb-shadow-sm`, `--lb-shadow-md`, `--lb-shadow-lg` | Increasing elevation/occlusion, **not** surface-layer step or color state | Retain current three CSS values initially in both modes ([theme](../src/styles/_theme.sass#L402-L405)); shadow opacity in dark is a later visual decision, not a reason to introduce `xl` now. Some components still use SASS shadows instead ([Dialog](../src/components/Dialog/LbDialog.vue#L264-L267)). |

**Global versus family surface:** preserve `--lb-surface-base`, `--lb-surface-subtle`, `--lb-surface-disabled` as canvas 1/2/3 sourced from the selected background (neutral by default), not aliases of `{c}`; `applyTheme({background})` supports a separate background source ([static](../src/styles/_theme.sass#L167-L175), [generator](../src/utils/color-generator.js#L265-L304)). Preserve `--lb-surface-overlay` as a backdrop, light 0.5 / dark 0.7 black alpha pending visual test ([theme](../src/styles/_theme.sass#L311-L312), [dark](../src/styles/_theme.sass#L784-L785)); it is not an alpha-tinted surface. Keep `--lb-text-light-normal`, `--lb-text-dark-normal` as opposite stable neutral luminance anchors for text-on-fill ([static](../src/styles/_theme.sass#L474-L478), [dark](../src/styles/_theme.sass#L791-L796)).

**Focus is distinct from active:** `--lb-border-{c}-focus` and `--lb-focus-ring-color` determine color; `base.$focus-ring-width` and `$focus-ring-offset` control geometry ([theme](../src/styles/_theme.sass#L315), [base](../src/styles/_base.sass#L122-L123), [Button](../src/components/Buttons/Button/LbButton.vue#L159-L163)). Do not introduce a new CSS width token without a compatibility/use-case decision. Validate visible keyboard focus against *both* surface themes independently of pressed/active styling.

### Family × mode application matrix

This table makes the palette decision explicit for **each family in both modes**. Each row uses the role sequence in the table above: text `11/12/9/7`, surface `1/2/3/4/5` (alpha `3/4/5`; inverse other mode `1/2`), fill `9/10/8/A4`, border `5/7/9/7/A4`. An exception is listed rather than silently inferred. These are intended mappings, not contrast test results.

| Family | Light palette and on-fill candidate | Dark palette and on-fill candidate | Exception / validation |
|---|---|---|---|
| primary | L sequence; stable light text | D sequence; stable light text | Orange fill contrast at normal/hover/active |
| secondary | L sequence; stable light text | D sequence; stable light text | Teal fill contrast |
| tertiary | L sequence; stable light text | D sequence; stable light text | Sky ≠ info blue |
| neutral | L sequence; stable light text | D sequence; stable light text | Fill/border disabled A2, not A4; check gray fill contrast |
| success | L sequence; stable light text | D sequence; stable light text | Green fill contrast |
| warning | L sequence; stable dark text | D sequence; stable dark text | Yellow fill contrast in each state, especially custom brands |
| error | L sequence; stable light text | D sequence; stable light text | Red fill contrast |
| info | L sequence; stable light text | D sequence; stable light text | Blue fill contrast |

Contrast decision rule for Step 06/07: for each of 8 × 2 × 3 fill states (and custom palette examples), measure actual foreground/background contrast; use the suitable neutral light/dark anchor per state without renaming public tokens. Target WCAG AA 4.5:1 for normal text (3:1 for large text and non-text boundaries); record exceptions instead of claiming the current candidates pass. For each alpha surface, composite over at least global base and subtle backgrounds in both modes and over the intended nested preview background; test text, icons, active states and borders after compositing. Surface alpha opacity is not equivalent to an opaque palette step. Do not describe focus color as a substitute for measured ring contrast/width/offset. On-fill for disabled fills may need a separate component policy; there is **no** existing `--lb-text-on-{c}-disabled`, so do not promise one here.

## Migration matrix for existing consumers (approved baseline; values untested)

“Unchanged” means **spelling and intended role**, not a guarantee that current `applyTheme()` values are preserved. Aligning runtime surface mappings to the static mapping **changes runtime appearance**; document and visually test the change even though names remain. No tokens are renamed or removed in Step 02.

| Old public name/pattern | Approved baseline / deferred item | Consumer action / compatibility |
|---|---|---|
| `--lb-text-{c}-{normal,contrast-high,contrast-low,disabled}` | **Unchanged** names/steps | Keep `contrast-high`/`contrast-low` order, not Sandbox's `high-contrast`/`low-contrast`; no rename. |
| `--lb-text-on-{c}[-hover/-active]`; stable `--lb-text-light/dark-normal` | **Unchanged** names; validate contrast-driven values | No alias to `--lb-text-{c}-on-fill` or unprefixed Sandbox names. If a value changes for contrast, flag visually in release notes. |
| `--lb-surface-{c}-{base,subtle,normal,hover,active}` | **Unchanged** names; runtime normal/hover/active 2/3/4 → 3/4/5, subtle 1 → 2 | Potentially visible behavior change after `applyTheme()`: test existing themes/components and state migration in Step 06; no name alias can preserve both meanings. |
| `--lb-surface-{c}-{normal-alpha,hover-alpha,active-alpha}` | **Unchanged** names; generate corresponding custom alpha primitives | Existing CSS-only consumers retain spelling; runtime custom themes gain the same roles only after Step 06. |
| `--lb-surface-{c}-{base-inverse,subtle-inverse}` | **Unchanged** names; resolve missing raw light/dark definitions | Existing CSS-only consumers may currently get an unset value: inspect/verify rendered use before release. |
| `--lb-surface-{base,subtle,disabled,overlay}` | **Unchanged**, distinct from family-specific names | Keep background-source behavior; don't alias global base to neutral family base if custom background differs. |
| `--lb-fill-{c}-{normal,hover,active,disabled}` | **Unchanged** | Preserve 9/10/8 and disabled alpha (neutral A2, others A4). |
| `--lb-border-{c}-{line,normal,active,focus,disabled}`, `--lb-focus-ring-color` | **Unchanged** | Preserve 5/7/9/7; don't alias focus to active. |
| `--lb-shadow-{sm,md,lg}` | **Unchanged** | No `shadow-xl` promised; elevation usage review separate from name migration. |
| Raw `--lb-{c}-{1…12,alpha-1…12}` and runtime `--lb-{c}-{light,dark}-{1…12}` | **Unchanged** where already present | Audit static availability of inverse dependencies before advertising raw variants as CSS-only API. |
| Runtime-only `--lb-border-{c}-subtle`, `--lb-surface-{c}-{raised,disabled}` | **Deferred; not promoted, aliased or removed by this contract** | Generator currently writes them, static token metadata does not ([generator](../src/utils/color-generator.js#L56-L61), [surface](../src/utils/color-generator.js#L99-L105)); owner must choose to promote or retire after consumer search. Until then, leave untouched and do not recommend for new usage. |
| Sandbox `--text-*`, `--surface-*`, `--fill-*`, `--border-*`, `--shadow-xl`, `light-dark()` | **Not aliases/imports** | Reference design concepts only; no unprefixed public names or changed theme engine implied. |

**Approved compatibility policy:** retain current `--lb-*` names throughout the initial modernization slice; no breaking token removal/rename in the first implementation slice. Treat visual semantic changes after `applyTheme()` as user-visible and record them in `CHANGELOG.md` with before/after examples when implemented. If testing shows a meaning cannot be reconciled without removal or a rename, pause for a separate owner-approved breaking release and an old → new/deprecated table plus a defined support window; do not silently repurpose or claim alias compatibility. Published package behavior and external downstream use remain unverified ([audit](audits/01-public-surface.md#L91-L96)).

## Recorded approval and deferred decisions

**Approved for planning:** keep eight current families and existing `--lb-*` names (including `contrast-high` and `text-on-{c}`); use static **1/2/3/4/5** surface steps in light and dark and align `applyTheme()` later; keep fill/border mappings and sm/md/lg shadows as the initial baseline; check on-fill contrast and alpha/inverse surfaces rather than claiming they already work; do not remove or rename tokens in the first implementation slice. Document runtime visual changes for existing custom themes. This approval covers the mapping and compatibility **contract**, not a release or a verified rendering result.

**Deferred, not silently decided:** Step 03 chooses theme selectors/system preference and inline-override ownership. Steps 04/06/07 test whether the candidate on-fill colors, alpha compositing, inverse references, focus and shadow treatment meet the intended roles. Runtime-only `border-subtle`, `surface-raised` and family `surface-disabled` are **not promoted** to supported static APIs or removed in this contract; assess consumers before either choice. Any breaking release or deprecation duration requires a later explicit owner decision if tests show a change is unavoidable.

**Next gate:** Step 03 theme/distribution contract; then Step 04 adds non-writing checks, Step 06 aligns static/runtime definitions and inverse references, and Step 07 tests modes, custom fills, alpha backgrounds and focus. No implementation is authorized by this record alone.
