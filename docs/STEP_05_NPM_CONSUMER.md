## Consumer evidence (2026-10-12)

- In a new temporary directory outside this repo, `npm install --ignore-scripts --no-package-lock littlebrand-ui-kit@0.8.3 vue@3 typescript@~5.9.3` installed the **already published** package. Node ESM successfully imported named components, plugin, `applyTheme` and `useSnackbar`. `import.meta.resolve('littlebrand-ui-kit/style.css')` resolved the published CSS file. No browser stylesheet rendering or bundler asset processing was tested.
- Strict `tsc` using `moduleResolution: "Bundler"`, `noUncheckedSideEffectImports: true`, and named root and CSS imports failed with **TS7016** (no root declaration) and **TS2307** (stylesheet module without type declaration). `require('littlebrand-ui-kit')` failed with **MODULE_NOT_FOUND**: published package exports `./dist/littlebrand-ui.umd.js`, while published `dist` contains `littlebrand-ui.umd.cjs`. Directly requiring that existing `.cjs` file returned expected named exports.
- **Isolated metadata simulation, not an installed release:** copied this branch's `package.json`, `types/` and five corrected `.vue.d.ts` files into that temporary published installation; the full strict fixture (`tests/fixtures/consumer-package.ts`) and both Node ESM/require root imports then passed against its existing 0.8.3 `dist`. This establishes that the chosen export conditions resolve with those *old* artifacts, not that a future build will emit the same files or that the release will include the declarations.

## Proposed fixes and maintained checks

- `package.json`: root `types` condition and `types` file included in npm `files`; `.cjs` require target agrees with the observed published Vite output; ESM root and both existing CSS aliases remain intact. CSS subpath `types` conditions enable strict TypeScript side-effect imports. No deep source imports are promised through `exports`.
- `types/index.d.ts`: explicit named public surface (all 33 component/piece names from Step 01, plugin, two Snackbar functions, five color/theme functions); reuse packaged `.vue.d.ts` where present and existing Snackbar source TS types. The seven components without declarations have **opaque** prop types, not invented completion. Button `tag`, Input `small`, Dialog's defaultable model and Popover `trapFocus`/Content props were corrected at their declaration sources; no component runtime was changed. Other individual declarations and generated MCP records remain unverified and may drift; Step 08/12 owns the broader repair. TypeScript `skipLibCheck` in the fixture does not certify all of their internal accuracy.
- `tests/fixtures/consumer-package.ts` self-imports every named public component, utilities/composables and both CSS aliases as an npm-style root consumer; its strict Bundler TS config also checks representative valid and invalid prop cases. `npm run typecheck` now runs it **after** source `vue-tsc`. This compiles against this checkout's `exports` via package self-reference; it is not a clean installed package test or actual IDE completion. `tests/contracts.test.js` checks export paths statically. `README.md` no longer promises unmeasured tree-shaking, and `CHANGELOG.md` records the prepared user-visible fixes as Unreleased.
- MCP CLI remains included in the published package (`mcp-server/dist/index.js` exists there), but the CLI was **not executed** and MCP dependencies were not changed. Root runtime dependencies must remain available to that CLI; do not remove them solely for bundle-size optics. Tree-shaking/bundle bytes and SSR/browser CSS behavior are **not verified**.
