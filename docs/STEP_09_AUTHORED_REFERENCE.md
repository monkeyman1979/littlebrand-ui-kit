# Step 09 — authored verified-slice reference

**Status:** Step 09 feature branch for review; not built, extracted, merged or published. Step 08 merged into `develop` via #128 (3186a6c). Published npm 0.8.3 and `main` are unchanged.

`reference/v1.authored.json` is the versioned, authored source for intent, use/avoid guidance, accessibility, states, dependencies, related stable IDs and four tested Vue examples (`reference/examples/*.vue`). The compound child shares the parent example: it cannot render alone. `scripts/generate-reference.js` derives prop names/types/requiredness from `.vue.d.ts`, defaults and source parity from implementations, slots/events from declarations, and checks selected tokens against compiled static SASS. It produces `reference/v1.json` (machine-readable), `docs/reference/v1/README.md`, `TOKENS.md` and five linked component pages. Token anchors are explicit stable IDs; the reference is intentionally limited to nine semantic tokens used by the slice, not an exhaustive catalog. Token mapping and theme contract remain in [Step 02](STEP_02_TOKEN_CONTRACT.md) and [Step 06](STEP_06_TOKEN_ALIGNMENT.md).

Examples live as mountable, typed Vue SFCs importing source exports. The generator substitutes the supported npm root import and adds the supported `style.css` import for documentation. `npm run typecheck` covers the source SFCs; `npm test` mounts all four and checks interaction plus generated-file freshness (`--check` does not write). Run `npm run reference:generate` after editing authored content or the verified APIs, then run `npm run reference:check`. Component extraction now uses the checked reference usage for the five verified names; **no extraction was run** for this PR, so the existing MCP data is still generic/stale and must not be advertised as verified. A future authorized release build/extraction must verify the resulting MCP/package artifacts against the exact release commit. Generic examples for the remaining catalog are not verified.

This is source-slice documentation, not a claim of published-package behavior, exhaustive type semantics, accessibility certification, screen-reader/browser coverage or MCP CLI verification. Root npm imports and CSS are primary; a registry, hosted MCP and deep imports are not offered. Release-artifact verification and MCP dependency audit triage remain open.
