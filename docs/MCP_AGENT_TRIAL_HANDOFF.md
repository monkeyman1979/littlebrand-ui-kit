## What “independent MCP agent” means

Yes: use a real AI agent with an MCP-capable client, give it a user task, and let it **choose** whether to call this server and which tools/results to use. A separate project is **not necessary to test tool discovery**: point the agent's MCP client at the *source* stdio server in this repo. A small disposable Vue+TS app is helpful for assessing the agent's resulting UI, but do not confuse installing published npm 0.8.3 with testing the new source changes. The installed package and tracked MCP `dist/` still have the old MCP tools and unverified release behavior. The client-specific MCP configuration is not prescribed here; use the absolute path to `mcp-server/node_modules/.bin/tsx` as the executable and the absolute path to `mcp-server/src/index.ts` as its argument, with the repo as working directory, after dependencies are installed. This is a **development-only** entry point, not a consumer npm CLI or hosted MCP URL. `tests/mcp-stdio.mjs` shows the exact source launch used by the deterministic test.

## What the MCP modernization did—and did not—do

- Step 10 replaced ten unverified source tools with three small, read-only, reference-backed stdio tools (`lb_search`, `lb_get`, `lb_setup`); Step 12A brought the checked total to six standalone examples. Source uses `McpServer.registerTool`, tool input schemas and read-only annotations. A real source stdio client already passes six deterministic retrievals, but an LLM choosing tools has not been verified.
- Remediation upgraded the dependency in both manifests/lockfiles to **`@modelcontextprotocol/sdk ^1.32.1` with `zod ^3.25.1`**; both lockfiles audited at zero findings at that checkpoint. This is the supported **v1 SDK line**, not an upgrade to the new v2 SDK or newest protocol revision. The [official v1 README](https://github.com/modelcontextprotocol/typescript-sdk/tree/v1.x) describes v1 as maintenance; the [official v2 migration guide](https://ts.sdk.modelcontextprotocol.io/v2/migration/upgrade-to-v2) documents split `@modelcontextprotocol/server`/`client` packages and a **Node 20+** prerequisite. This repo's MCP package currently declares Node `>=18`. A v2 migration needs a separate Node support/compatibility decision, implementation PR and independent tests; do not imply this source server already implements v2 or a hosted HTTP transport. Stdio remains the local-first scope; newer SDK does not by itself prove agents use the reference well.
- Re-audit both lockfiles near a release decision because advisory results can change. With **separate owner authorization** for release-artifact generation, validate a package from the exact release commit: new extracted/compiled MCP CLI rather than old tracked `dist/`, fresh npm consumer installation, Vue/TypeScript imports, CSS, browser behavior, and CLI tool/answer parity. Do not publish, deploy, or merge into `main` without separate approval. Keep npm primary; source registry and hosted MCP are future options, not deliverables.
