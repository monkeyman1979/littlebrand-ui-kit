Tests operate on committed source and generated data **without regenerating them**. A deliberately invalid `variant="imaginary"`/missing required prop is rejected by `usageIssues`, and deletion of an essential token from an in-memory set is reported by `missingRequiredTokens` ([contract tests](../tests/contracts.test.js), [helpers](../tests/helpers/contracts.js)); changing the actual data adds an unexpected issue and fails the baseline comparison. Do **not** run `npm run build`, `npm run extract*`, `npm run build:mcp` or `npm install` as part of routine validation; dependencies are now declared in `package.json` and checked into `package-lock.json` for a normal install in a clean environment. The installation used to add test tooling was done with `--ignore-scripts`; no release build ran.

## Pinned known legacy failures (pass only while exactly accounted for)

The tests intentionally pin the current mismatch **set**, rather than turning these checks off or claiming the defects are solved. New mismatches fail; when a legacy mismatch is fixed, update the expected list and this document in that fix's PR. Source evidence is in [Step 01](audits/01-public-surface.md) unless noted.

- **Public metadata coverage:** `LbBadge`, `LbBottomSheet`, `LbChip`, `LbNavigationBar`, `LbNavigationBarItem`, `LbSnackbar`, `LbSnackbarProvider` have no same-name `.vue.d.ts` or MCP record. `LbDropdown` is missing from the secondary barrel but is root-exported/plugin-registered. Checks compare all names and allow **only** these known differences ([inventory test](../tests/contracts.test.js)).
- **Generated usage:** `LbCalendar` and `LbDialog` advertise invalid `variant="filled"`; `LbCustomSelect`, `LbMenu` and `LbSelect` omit required `options`; `LbRadio` and `LbSegmentButtonItem` omit required `value` (and the latter needs a parent). Generated Button usage has no label/default content ([usage tests](../tests/contracts.test.js), [generator](../scripts/extract-components.js#L145-L169)). The syntax/prop checker is focused: it does **not** validate all Vue semantics, dependencies, slots, event payloads or whether every generated snippet runs.
- **Token names:** literal component CSS references `--lb-focus-ring-offset`, `--lb-focus-ring-width`, `--lb-neutral-a4`, `--lb-neutral-a6`, and `--lb-surface-neutral-disabled`, which are not defined by static `_theme.sass` or `_colors.sass` ([source reference](../src/components/Popover/LbPopoverTrigger.vue#L110-L113), [Chip](../src/components/Chip/LbChip.vue#L405-L408), [Switch](../src/components/Switch/LbSwitch.vue#L150-L153)). Interpolated SASS variable references and 32 static inverse raw-scale dependencies are outside this literal-reference check; [Step 02](STEP_02_TOKEN_CONTRACT.md) tracks inverse resolution. Do not invent replacements without the token contract.
- **Theme:** explicit `.dark` class toggling updates the raw color scale in the DOM emulator. The runtime generator still uses old surface step mappings, lacks alpha surface semantic keys, and does not detect `data-theme="dark"`; an observer created by the first `applyTheme()` call can restore that first palette after a second call ([theme tests](../tests/theme.test.js), [generator](../src/utils/color-generator.js#L98-L105), [observer](../src/utils/color-generator.js#L307-L322)). System-preference default, explicit light, nested previews and contextual Dialog teleport theming are **not implemented** or claimed covered by this test; use Step 07 browser tests after Steps 03/06 decisions land.
- **Lint/type baseline:** only the Badge type annotation was changed to permit a strict SFC pass; for legacy unused values/unnecessary escape and redundant assignments, limited per-file ESLint exceptions are documented in [config](../eslint.config.js). These are not blanket ignores; expand lint coverage after legacy cleanup without masking new defects.
